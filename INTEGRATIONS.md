# Подключение провайдеров

Провайдеры пока не согласованы. Реализованы регистрация и выбор адаптера по типу и имени, проверка доступности и контракты платежей и SMS. Реальные адаптеры добавляются в Infrastructure после получения спецификации API и тестового доступа.

Пустая конфигурация оставляет интеграции недоступными. GET /api/integrations/availability требует права qsr.pos и возвращает доступность Payments, Sms, Delivery и Fiscalization. Секреты и имена подключений в ответ не включаются.

Адаптер реализует IIntegrationProvider и соответствующий специализированный интерфейс. Зарегистрируйте его через AddScoped<IIntegrationProvider, ConcreteProvider>(). Выбор задаётся переменной Integrations__Providers__Payments или Integrations__Providers__Sms со значением Name адаптера. Для доставки и фискализации предусмотрены категории выбора. Их операционные контракты требуется определить по согласованным API и формату чеков.

IPaymentProvider разделяет создание платежа, проверку статуса и возврат. Каждый запрос создания или возврата передаёт ключ идемпотентности. Статус Unknown сохраняет неопределённый исход, например при потере ответа после списания. Он требует сверки с провайдером до повторной отправки финансовой операции. Платёжный обработчик и callback пока не соединены с этими контрактами.

ISmsProvider сообщает о приёме сообщения провайдером. Подтверждение доставки требует отдельного API или callback конкретного поставщика.

При реализации адаптера нужно проверить подпись callback, защиту от повторов, соответствие суммы и валюты, тайм-ауты, правила повторов и тестовую среду поставщика. Секреты передаются из внешней конфигурации. Формат аутентификации определяется документацией выбранного API.

Эта версия содержит подготовку подключения. Рабочие банк, SMS, доставка и фискализация ещё требуют реализации адаптеров и проверки на тестовых средах. Полное соответствие QSR всему ТЗ ещё не достигнуто.

Проверка этой версии: сборка без ошибок и предупреждений, 4 теста прошли, 1 PostgreSQL-тест пропущен без тестовой базы.
