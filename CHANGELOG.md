# QSR — доработка и проверка

Исходник: локальный архив `QSR.zip`. FootCamp использован как образец оформления контроллеров. В архиве сохранены слои Domain, Application, Infrastructure, WebApi и CentralApi, а также исходное ТЗ.

- Исправлены ссылки между проектами, регистр пути WebApi и пространства имён конфигураций EF Core. Восстановлены запуск WebApi и регистрация зависимостей. Шаблонный маршрут погоды удалён.
- WebApi проверяет JWT через HTTPS-адрес провайдера, аудиторию, доступ к филиалу и разрешение для заказов или склада. Настройки подключения и авторизации передаются извне. Ошибки возвращаются через Problem Details; внутренние исключения не раскрываются клиенту.
- Создание заказа требует UUID в заголовке `Idempotency-Key`. Ключ и отпечаток запроса сохраняются вместе с заказом. Повтор тела возвращает тот же заказ; другое тело с тем же ключом возвращает 409. При одновременных запросах уникальный индекс предотвращает дубликат: получив 409, клиент может повторить тот же запрос с тем же ключом.
- Добавлена начальная миграция PostgreSQL. Настроены поля Money, ограничения и маркеры конкурентного обновления для заказов, остатков, платежей и кухонных задач. Многошаговые операции принятия, отмены и возврата сохраняют общую транзакцию. Порог полного возврата считается по фактически принятым платежам. Внешние идентификаторы платежей и возвратов защищены от дублей в базе.
- Для рецепта выбирается последняя активная версия, действующая на момент запроса. Фоновая задача раз в минуту обновляет снимок низких остатков в Redis; при отсутствии снимка API читает PostgreSQL. Снимок служит для отчёта и не участвует в списании.
- Docker Compose включает PostgreSQL, Redis, отдельный запуск миграции, WebApi и CentralApi. Redis и PostgreSQL не публикуют порты на хосте; HTTP-порты API доступны на loopback.

## Проверено

- Сборка .NET 10: 0 ошибок и 0 предупреждений.
- Тесты: 2 прошли, 1 интеграционный тест пропущен. Проверены неизменность остатка при недостатке и совпадение модели EF с миграцией. Идемпотентный SQL-скрипт миграции сгенерирован.
- Оба API запущены локально. `/health/live` у обоих вернул 200. Заказы и складской отчёт без токена вернули 401. Конфигурация Compose прошла проверку `docker compose config --quiet`.

## Запуск и ограничения

Для Compose задайте `POSTGRES_PASSWORD` (для локальной связки используйте случайную строку без спецсимволов строки подключения), `QSR_BRANCH_ID`, `QSR_AUTHORITY` и `QSR_AUDIENCE`. Из корня проекта: `docker compose -f Docker/docker-compose.yml up --build`. Токен для WebApi должен содержать `branch_id` с UUID филиала и `scope` со значением `qsr.orders` или `qsr.inventory`. Перед внешним доступом настройте TLS на входном прокси.

Миграция рассчитана на пустую базу. Для существующей базы сначала сравните её схему с миграцией. Для интеграционного прогона задайте `QSR_TEST_POSTGRES` строкой подключения к отдельной тестовой базе и выполните `dotnet test Solution.slnx`. В этой среде локальный PostgreSQL не смог создать область общей памяти, а Docker daemon не был запущен. Применение миграции на живой БД, работа с Redis и полноценный запрос с токеном от реального провайдера не подтверждены.

CentralApi предоставляет проверку запуска. Полный жизненный цикл POS/KDS по HTTP, управление филиалами, синхронизация меню, офлайн-режим, лояльность, доставка, фискализация и интеграции с платёжными провайдерами остаются отдельными этапами ТЗ. Уникальные внешние идентификаторы платежей и возвратов не заменяют контракт идемпотентности с провайдером.
