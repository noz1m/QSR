# Проверка QSR 17 ноября 2026

Применены миграции InitialBranch, CashShifts, BranchCatalog и CashEntryAssignedIds в тестовой PostgreSQL 17 в Docker.

14 тестов прошли, 0 пропусков. Сквозной тест на уровне Application создаёт меню, категорию, две станции, товары и рецепты, оформляет заказ, повторяет создание с тем же ключом, принимает наличные в открытой смене, повторяет оплату, принимает заказ, проверяет списание ингредиентов, проводит обе станции через приготовление и завершает выдачу. Отдельно проверяются конфликт обновления остатков и уникальность ключа заказа. Redis проверен реальными записью, чтением и удалением значения.

Сквозной тест выявил ошибку отслеживания новых кассовых движений EF Core. Для CashEntry установлен ValueGeneratedNever, поскольку идентификатор назначается доменной моделью.

Резервная копия тестовой базы создана pg_dump и восстановлена pg_restore в отдельную временную базу. Чтение таблицы orders после восстановления успешно. Проверочная база удалена скриптом. После штатного перезапуска контейнера PostgreSQL число заказов сохранилось.

Базовая проверка чтения БД через pgbench выполнила 1000 запросов SELECT count(*) FROM orders с 10 клиентами без ошибок. Это малая тестовая база. Результат не подтверждает p95 API и производительность при рабочей нагрузке.

HTTP-сценарий с реальным провайдером авторизации, потеря связи во время финансовой операции, автономная синхронизация и полноценная нагрузка приложения ещё не проверены. Мобильные и веб-интерфейсы, центральное управление, лояльность и доставка остаются незавершёнными. Полное соответствие ТЗ ещё не достигнуто.

В новой версии наличная оплата требует shiftId и claim sub. Настройка каталога доступна с правом qsr.catalog. Исходные SourceTemplateId должны ссылаться на утверждённые шаблоны при подключении центрального управления.

Миграция BranchCatalog добавляет внешний ключ товаров на категории. В старой базе с товарами без категорий необходимо сначала подготовить реальные категории и меню с соответствующими идентификаторами. Тест миграций выполнен на пустой базе, автоматическое восстановление неизвестной иерархии старых данных не реализовано.

Повторный запуск тестов:
QSR_TEST_POSTGRES="<строка подключения к отдельной тестовой базе>" QSR_TEST_REDIS="<тестовый Redis>" dotnet test Solution.slnx

Резервное копирование:
scripts/backup-postgres.sh <контейнер> <база> <пользователь> <новый файл.dump>

Проверка восстановления:
scripts/verify-backup.sh <контейнер> <пользователь> <файл.dump>

Dockerfile собран из исходников в образ qsr-branch:verification без предупреждений. Контейнер вернул 200 на /health/live и 401 на запрос каталога без токена. Проверен запуск с реальными PostgreSQL и Redis. Использован тестовый адрес провайдера JWT, проверка реального входа и авторизованных HTTP-операций ещё не выполнена.

При остановке Redis фоновая задача зарегистрировала ошибку, приложение продолжило отвечать 200 на проверку запуска. После запуска Redis и удаления старого ключа задача автоматически восстановила снимок остатков. Это проверка восстановления фонового кэша, а не полноценного автономного POS.

Удалена неиспользуемая зависимость AutoMapper 16.2.0, для которой NuGet при контейнерной сборке сообщил предупреждения высокой серьёзности. Повторная сборка образа и восстановление пакетов прошли без предупреждений.

Добавлены маршруты настройки каталога:
GET/POST /api/catalog/menus
POST /api/catalog/menus/{menuId}/categories
POST /api/catalog/categories/{categoryId}/products
GET/POST /api/catalog/stations
Для них требуется scope qsr.catalog. Создание товара проверяет принадлежность категории и активной станции филиалу. Обновление каталога, варианты и модификаторы через API ещё требуют реализации.
